## 一、系统身份与范围（必须保持）
这是包含**65名固定虚构人物 v4.1**的罗马尼亚财经内容／模拟交易／编剧工作台，不是 Brantone Veylor CRM，也不是单独的真实客户端／后台子账户／总账户交易平台。65人的唯一正式人物资料来自 `skills/romania-market-director/characters/index.json` 和 `characters/profiles/*_AI_Profile.json`；旧70/72人代码及记录不得混用。当前系统四个浏览器入口：新闻 `/`，65人模拟交易 `/trading`，财经 Skill `/skill`，图片编辑外链 `/trade-platform`（仅保留兼容旧链接）。

## 二、模块① 新闻推送、财经资讯核验与审稿

**已找到的实现：**
- `tools/finance_skill_api.py`、`tools/finance_skill_hub.py`：网页准备按钮、按需调用官方 BVB RSS 抓取、去重与待审候选队列、结构化审核包及手工确认规则。
- `.agents/skills/romania-stock-intelligence/`：罗马尼亚股票情报审核，财经观察的来源、日期和输入结构检查。
- `tools/content_routing.py`、`tools/news_materiality.py`、`tools/editorial_storyline.py`：内容类别、重要性候选排序、16节点与对话衔接。审核前不准作为已核实新闻发布。
- `skills/accuracy-enhancement/`、`skills/bvb-fact-check/`、`skills/news-priority/`、`skills/script-qa/` 等增强包及测试。
- 代码强制输出 `BLOCKED_NO_AUTOMATIC_PUBLICATION`；消息只供教育／编辑审阅，不能直接成为真实交易建议。

**尚未完善：**
1. RSS抓取是**手动按需执行**，没有确认的后台定时采集、监控告警、自动发布调度或 WhatsApp 推送。
2. 数据结构和引用格式的核验不等于独立核实新闻原文、BVB 最新股价、涨跌和权重；仍需可靠实时数据源、双源交叉验证、失效重试和可打开的原文链接。
3. 新闻图与指标图需要已验证数据；不能自动拿合成数值充数。部分媒体资料仅有目录索引，不具备完整可调用原件。
4. 完整审核链需建立编辑/复核/批准角色的持久审批记录、撤回和可追溯审计，并检验多语种事实准确性。

## 三、模块② 65人物模拟股票交易与持仓

**已找到的实现：**
- `tools/trading_65.py` 和 `tools/trading_65_ui.py`，由 `tools/finance_skill_api.py` 提供 `/api/trading/sim/state`、`/api/trading/sim/action`、`/api/trading/sim/snapshot`。
- 界面包含65人资料搜索、模拟开户与资金条件、参与频率、指定当天参与、建立股票计划、候选人员推荐、确认邀请、拒绝、模拟买入、持仓和卖出、已确认买卖记录与只读快照。
- 服务端为模拟买卖添加身份、最少股数、可用模拟资金、邀请前置条件、不可重复买入、最短持有日检查，并采用本地状态原子持久化；并不连接交易所或真实券商。
- 65份完整人物档案与索引需通过 `validate_persona_roster.py`；拒绝不存在的人物编号和错配档案。

**尚未完善：**
1. 已创建股票计划编辑（`edit_offer`）缺失。
2. 按股票统计不同持有人数的图表与可视化分析未对等实现。
3. 批次持仓、批次卖出和到期成员选择操作未对等实现；当前卖出逐个持仓。
4. 最早可卖日期仅有条件判断，没有完整实时倒计时界面。
5. 历史手动持仓录入、独立每日买入清单及交易参数管理尚未完成旧版对等。
6. 模拟价格和资金为人工设置，不是行情／成交价；不能显示为真实投资收益，亦没有多端云端账本同步与版本化审计。
上述差距源于 `docs/LEGACY-TRADING-FUNCTION-PARITY.md`；旧代码只保留在完整备份的 `legacy/`，在新版未实现并验收前不得删除。

## 四、模块③ 财经 Skill、65角色群聊编剧、课程与长期记忆

**已找到的实现：**
- `tools/chennan_writing.py` 与 `tools/chennan_writing_ui.py` 提供日期、16个时段节点、助理/教授原话、人物选择、全档案提示词复制、JSON草稿导入、角色/格式审核、正式采用会话、文档保存及回看。
- `tools/role_voice.py`、`tools/storycraft_contract.py`、`tools/dialogue_quality.py`、`tools/skill_execution_contract.py` 校验角色语言层级、对白冲突与身份、文风偏移、记忆引用来源和教授课程限制。
- 人物固定65名、每人档案稳定；未通过审核的草稿不能自动写入正式记忆。正式采用会话保存本机，与新闻状态及模拟持仓状态隔离。
- 现有工作流支持调用**你自己的 ChatGPT**：网页生成包含人物档案的提示词，复制到 ChatGPT 后把 JSON 粘贴回网页校验。可选本地 Ollama 生成内部草稿，前提是本机安装模型并通过状态检测。
- 辅助规则涵盖上午35条、下午35条、晚间30条的弹性目标（±2–3），助理八项内容及19:30教授课程场景；这些是内容制作规范，不是自动群发系统。

**尚未完善：**
1. ChatGPT Plus 会话不等于本地网页可直接调用的模型 API；目前没有经验证的无需粘贴、全自动端到端人物对话生成链。
2. 人物的长期记忆目前主要是本机正式会话存储，缺跨设备/团队同步、备份、冲突合并与恢复机制，不能把未采用草稿当记忆。
3. 虚构人物自然口语、罗马尼亚语地域贴合、不同角色口吻差异仍需人工逐场评价；正则校验不能证明自然度。
4. 教授正式完整课程、新闻事实验证、GIF/图片取材、真正的消息发布与回执闭环都未做全量实机验收。
5. v4.1列出的12 GIF和8 PNG主要是索引／云盘引用；仓库里的旧媒体不等于新版媒体原件全已落地。

## 六、共用 UI、身份、数据、部署及质量
