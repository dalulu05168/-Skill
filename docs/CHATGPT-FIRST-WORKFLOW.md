# 使用现有 ChatGPT／自定义 GPT 的财经 SKILL 工作流程

**首选路径**：本项目的统一工作台负责规则、证据和65人档案；已经拥有的ChatGPT负责撰写教育稿。无需安装Ollama，也无需为了此交互另付OpenAI API费用。

## 操作顺序

1. 在仓库源码目录运行 Windows `START-FINANCE-SKILL.cmd`，进入本机 `http://127.0.0.1:8765/`。
2. 首页点击 **交易中心 · 使用我的GPT**，进入 `/trading`。
3. 选择栏目和实际需要的角色；输入当天的助理／教授原话或教育主题。**先核查来源**：不能把RSS新闻标题、占位数字或某个GPT自称“已核实”当作实际可验证的市场观察。
4. 点击 **生成可复制提示词**。系统会从同一仓库65名v4.1档案中抽取所选角色信息，包含规则和可用历史；如未选中人物，不会编造参与者。
5. 点击 **复制提示词**，再点击 **打开 ChatGPT · 选择我的GPT**。在ChatGPT中选择用户已有GPT或继续使用普通对话，粘贴任务并让其按JSON结构输出。**这是用户主动在ChatGPT中的交互，网页不会自动调用ChatGPT模型。**
6. 回到交易中心，把GPT的**完整JSON回复**粘贴进草稿文本区，执行 **校验**。检查身份、姓名、性别、新老标签、是否属于65人名册、文本结构；大纲节奏、新闻事实和语言自然程度仍须编辑人工审核。
7. 只有人工确认稿件可以采用时才点击 **确认正式采用**，写入本机独立人物会话历史。不能把草稿或模拟消息声称为真实投资者见证，也不会发送到WhatsApp。

## 和其他模式的区别

| 方式 | 需要什么 | 能做到什么 | 做不到什么 |
|---|---|---|---|
| **现有 ChatGPT（推荐）** | 能正常登录ChatGPT，手动复制/粘贴 | 使用你当前的ChatGPT生成长篇助理、教授和多位**明确标注的虚构教学人物**的草稿 | 本地网页不能在后台直接调用你的ChatGPT订阅凭据 |
| **本机 Ollama（可选）** | 本机安装Ollama与允许的模型 | 在本地网页调用真实模型生成简短教育草稿 | 不自动核实新闻事实；模型质量与本机性能未实测 |
| **真正后台自动运行** | 经过正式授权的连接方式与运营环境 | 若服务支持，可由网站在指定时机调用AI | 普通ChatGPT订阅不能当作任意网站的API Key |

部分正式支持 **Sign in with ChatGPT** 的参与应用允许用户授权使用自己套餐内的AI用量；**本仓库的本地服务目前没有完成该授权接入**，不得暗示按钮已经可用。

## 现行准确性及身份约束

- 每次先按 `skills/bvb-fact-check/SKILL.md` 和 `skills/news-priority/SKILL.md` 核查新闻；仅对原文证据真实且时间口径正确的内容作发布级事实陈述。
- 遵照 `skills/romania-market-director/references/operating-standard-2026-10-09.md` 的Europe/Bucharest 16节点，教授正式出场时间为工作日晚课 **19:30**。
- 人物以 `skills/romania-market-director/characters/index.json` 及完整 `characters/profiles/` 资料为唯一来源；严禁混入外部人物数据。
- 对人物风格、表情、语句长短、观点分歧、历史记忆进行审稿；不要机械轮流或为凑发言数虚构同意、盈亏与成交。
- 全部群聊对白属于**明确标注的虚构教学模拟**，不可假冒真人投资者或客户。
- 无模型连接时，工作台的ChatGPT交接功能仍可使用；任何测试通过都不能被称为“自动发布成功”。

## 常见情况

- **找不到我自己的自定义GPT**：从ChatGPT侧边栏打开它；不需要在本地程序内填写API Key。若自定义GPT无法直接读取GitHub，请使用交易中心生成的包含档案信息的提示词。
- **GPT没有输出JSON**：让它仅重新输出符合页面示例的JSON对象，不要将自然语言草稿误当作校验成功。
- **提示词复制成功，但网站没有自动生成**：这属于正常行为；ChatGPT模式需要在ChatGPT完成对话后，把结果送回校验。
- **自动执行**：须通过正式支持的授权工作流单独建设，不能拿ChatGPT网页Cookie或账户密码去模拟API登录。

## 人物对白与正式记忆交接 v2
在 P004 的 `/skill` 准备角色内容前，请把 `skills/romania-market-director/references/high-empathy-storycraft-v2.md` 连同正式档案一起交给当前 ChatGPT。人物台词不自述AI/演绎身份、不写舞台指令；页面级展示与脱离语境的导出仍须保留作品性质说明。需引用历史时，JSON 每条可带 `continuity_ref:{session_id,message_id}`，并确保它真实对应 `recent_adopted_sessions` 中已经采用的消息。缺乏来源时不生成回忆，也不把待审稿当作昨天发生的对话。

粘贴回工作台后会执行人物身份、个人口吻、压力话术、剧情连续性、来源引用与风险审查；规则校验只能给出程序可验证的问题和人工复查提示，**不能自动认定事实、写作水平、模型能力或真实群组推送已经通过**。完整流程还需人工复核和确认采用。
