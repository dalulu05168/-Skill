# 模块一：限时财经采集与大盘分析（2026-10-11）

## 唯一目标（用户本轮收敛）
只执行四件事：
1. **按时间采集**：采用原有 Europe/Bucharest 16 节点表，不擅改时间；每个节点只处理所属采集窗口内、确实标注了发布时间的事件。每次请求即时拉取/使用不超过270秒的缓存，不代表后台持续运行。
2. **热点新闻**：保留 BVB 官方市场公告、发行人披露、交易所公告、ECB 公告、BURSA 媒体来源。报告把高优先级 P0/P1 与普通 P2 分开；来源不通或文章无时间/域名不符直接显示错误，不混入当前事实。
3. **真实性审核**：只把官方来源归属、时间和链接视为“元数据初核”；**绝不**自动标注“文章事实已证实”。原文财务数字、交易日、量纲、权重和独立证据需要逐项核对，完成前状态是待核实。仅因媒体报道或关键词匹配不能定性股市因果关系。
4. **市场大盘分析**：优先 BET 与权重股、行业结构；官方延迟 BET 报价不足60分钟且带时区的情况下才给出**临时方向观察**，仍不代表价格真实核验；缺失、过时、格式错误时明确“无法判断”。**不虚构实时价、成交额、行业贡献或收益**。

不启动人物、剧本、自动发群、股票交易、图片处理或独立翻译 Skill；这些是四合一其他模块的职责，不能借此删除其已有数据。

## 本次仓库改动
- `tools/bvb_window_audit.py`：节点窗口识别、RSS 事件时间归档、来源白名单、紧急性候审、真实性待核实标记，以及 BET 报价的新鲜度检查。
- `tools/bvb_v33_api_cloud.py`：增加 **`GET /api/window-brief`**（默认当前生效节点）和 **`GET /api/window-brief?node=RO-07`**（必须是当天已进入准备时段的节点）。返回 JSON，绝不自动公开发布。
- `tools/test_bvb_window_audit.py`：离线固定样本测试 16 节点、夏令时、窗口边界、媒体来源伪造、缺失数据和市场方向审慎判断。
- `.github/workflows/skill-quality.yml`：加入这组测试作为 CI 门槛。

## 不能夸称已经完成
- 这个 `/api/window-brief` 在仓库**开发分支**中，不等于 invest.sasakic.cc 已开通此 API。Render 静态预览服务无法执行 Python API。
- `bvb_v33_api_cloud.py` 的源采集部分可以请求网络，但真实外部 RSS / BVB 报价的可用性没有在生产网络端到端确认。当前还没有持久化后台调度，也没有获授权的实时行情供应商。
- 没有完成每条热点新闻的自动内容核验；没有可核验的银行/能源板块权重和成交结构，不会生成伪造的大盘原因分析。
- 最终中文分析需依据原始罗马尼亚语/英语来源重新编写；这次没有引入独立翻译 Skill 或假定机器翻译即事实。
- 不修改原始 BVB v3.3 文件或浏览器 localStorage；原草稿未迁移，禁止无备份切域名。
