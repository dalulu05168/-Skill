# 65人交易中心：移除旧70人源码及功能迁移说明

本仓库正式只保留 **65人（01–65）教育模拟交易代码**，旧 `legacy/005-trading/` 的70人JS及其旧测试不再作为当前源码保留。移除对象只包括旧程序与直接测试，并不删除65人档案、现有交易数据或外部 `005` 仓库。历史源码可从 [移除前Git提交](https://github.com/dalulu05168/-Skill/tree/23163f3ac5cc0fdf4a1194b264de8e1ce1dfa75e/legacy/005-trading) 复原（包含其原始两份JS）。

## 保留并修顺的65人流程
1. 在 `/trading` 选择01–65号正式人物，手动配置**模拟开户**、币种及模拟资金。
2. 新建BVB/其他市场的**模拟股票计划**；允许在**首次生成推荐之前**编辑。一旦产生推荐、计划或持仓，禁止变更原计划，以免重写历史事实。
3. 基于当日日期、资金门槛及参与频率生成候选成员。邀请或拒绝仅改变对应日期的计划，不允许重复点击重置已邀请/买入状态。
4. 仅对已邀请成员进行人工确认**模拟买入**；记录持仓与单独交易事件，拒绝超预算、无邀请或重复持仓操作。
5. 从保存的活跃模拟持仓实时计算**按股票去重持有人数**，仅绘制人数统计，不伪造行情曲线。
6. 展示每笔持仓的最早可卖时间与动态倒计时；到期后可逐笔卖出，或仅选取**同一股票计划**中已到期的持仓批量卖出。每笔都有独立交易记录，批次ID用于审计；整批检查通过后才落库。

账本使用 `trading-65.json`，用户本地和云端部署各有独立数据目录；`/api/trading/sim/state` 是只读概览，变更必须显式提交到 `/api/trading/sim/action`。所有股票价格、成本和资金都是**用户手动输入的模拟值**，没有券商实盘和真实自动成交。

## 明确不迁移的旧70人功能
- **旧版手工持仓导入**：不再允许不经过模拟邀请和买入确认就复制旧持仓；防止70人资料串号。
- **旧版独立每日买入名单**：使用已有65人股票计划+日期推荐功能，不引入独立70人成交/名单逻辑。

历史数据只保存在其原独立项目/仓库提交，**绝不按相同01–65编号映射**到本系统；本次仓库变更不删除线上旧记录。

## 验收边界和发布门禁
- 必须执行 `tools/test_trading_65.py`、`tools/test_trading_65_api.py`、`tools/test_legacy_trading_parity.py`、独立人物来源测试和完整CI。
- 再做浏览器/手机端点击测试：空数据、权限、买入、拒绝、重开、到期卖出、批次拒绝回滚、刷新/重进数据还在。
- 云端部署必须备份验证 `/var/data/trading-65.json`（或实际挂载盘），核对发布SHA和账号认证后再上线。
- GitHub绿色CI只说明对应测试通过，不等于已完成真实浏览器、云端数据恢复或生产验收。未经独立验收不要直接发布生产版本。
