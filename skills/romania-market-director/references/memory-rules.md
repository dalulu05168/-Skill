# 成员发言记忆与连续性

固定档案characters/profiles/不可因单场剧情变化；动态状态与发言记忆单独保存。默认角色记忆字段模板为templates/member-memory.json，当前持久化资料位于memory/state.json。

写作前读取已有事件，再检索入选角色说过的观点、被谁回应、理解、疑问及近期措辞。结束后输出记忆差异，用户批准或明确授权记录后才写入实际状态。提供初始空状态不等于历史已迁移；不能把示例、草稿当作已采用的课堂剧情或实际授课。

每条记忆应有scene_id、消息引用、日期/时段（未知允许null）、角色id与状态。记录重要的观点、回答、仍未解决问题、观点变化原因、表达/表情使用、下场可回收线索。不记录每个无意义的收到。

同一问题被回答后可进一步追问，但不重新伪装成从未提出过。理解部分内容不代表赞同全部内容，知识与信任不无依据跳变。既往问题无新证据时允许持续未决。

只记录虚构剧情中的实际写出且被采用内容，不写真实客户交易、持仓或收益。示例记忆只能留在对应示例里。丢失记忆时说明无法确认历史，不编昨天发生的事。

跨GPT迁移必须随包提供memory/state.json及已有事件。上传、检索、长上下文和写文件能力取决于平台，不声称自动永久记住。写入用稳定scene_id防止重复，保留事件引用，不静默覆盖历史。冲突记录进入待确认列表。

## 最新编辑定稿归档流程（v2.3.0）
用户每天发回个人修改的正式完成稿，**当且仅当明确表明采用/最终定稿**时，比较源稿、以用户版本为准做逐人记忆抽取并主动发起GitHub写回：`library/approved/日期_栏目_版本.md`存原文，`memory/state.json`合并角色事件与未决问题，`library/index.json`登记采用来源、日期、版本和是否虚构。留住角色最近观点、正常口头禅、表情/GIF使用、谁回应谁、疑问答案、认知变化原因、连续剧情和八项已用主题；每条需稳定scene_id/message_ref/所属时段。修订同scene时有版本，不丢历史，不给所有人凭空加记忆。写入前再次校验ID/姓名/性别/老新身份；禁止根据已采用错误旧稿修改固定人设。
如果用户只是发送“修改建议/帮我检查”，只形成候选记忆差异供确认，不升级为正式历史。GitHub不可写、云盘无明确权限或操作失败时给出待保存文件和真实失败状态，**不得宣称自动已上传**。只保存实际采用的虚构剧情，不包装成真实群用户记录/交易收益。编剧前先读最新版记忆，用户定稿后再更新，别把草稿当历史。
