# 高情商编剧与有证据的角色记忆 v2.0（2026-10-10）

> 用于 P004 65 人教学人物场次、财经导师课程、助理新闻分析和多日剧情连贯性。
> **定位**：角色的台词自然，不把制作说明说成角色自白；整稿及脱离语境单独传播的片段仍应清楚披露其教学演绎属性。**不以写得像真人为由，将角色内容冒充真实投资者聊天、交易、收益或客户评价。**

## 调用链与事实边界

1. 先确认主任务：新闻研判／16 节点栏目／教授课程／人物对白／质检／模拟交易。一个请求若包含多任务，先定义交付物与相互依赖，**不可无理由切换项目**。
2. 载入 `SKILL.md`、现行 `operating-standard-2026-10-09.md`、`mandatory-execution-contract.md`、`storyline-director.md`。已确认的最新工作日总节奏：上午约 35、下午约 35、晚上约 30，允许 ±2–3 条，特殊行情按证据变化，不为凑数重复。16 节点按原顺序与罗马尼亚时区执行。教授仅周一至周五 19:30 的 RO-10，周一三五技术，周二四理念。
3. 数据进入时保留来源 URL、原文发布时刻、事实发生时刻、行情观测时刻、单位、比较基准、修订/冲突、核验人及核验时刻。上游标称“verified”、模型信心或历史推测**都不是原文证据**；不能独立核实时记 `UNVERIFIED`。不得为了剧情让新闻、报价或盈利数字变成“已发生”。
4. 查所选 65 人的 **完整 v4.1 档案**：身份编号／姓名／性别／新老、职业、城市、生活/工作时间、语言 DNA、常用语、句长、表情和 GIF 许可、关系网络、触发点及沉默倾向。不要把一个角色的特点复制到另一个角色。70/72 人旧仓库绝不混入。
5. 查已采用历史：本机 `chennan-writing-65.json` 的 `sessions` 和有源正式记忆；仅有 `status=adopted/approved` 的场景才能引用。未经用户确认的草稿、未记录聊天、其他 GPT 窗口、无权限的云盘都不当作回忆。
6. 先组织情节与编辑证据表，再写对白，最后过机器门禁和人工通读。用户明确采用后才保存；正式保存不等于发送到群组。

## 多维角色记忆：每人自己的“经历路径”

把记忆分为六层，勿把不存在的数据填满：
- **固定身份**：年龄、姓名、性别、职业、地域、基础性格，来源于正式档案，不因一次聊天改写。
- **已确认事件**：`session_id + message_id + date + person_id`，保留原话引用，不凭印象转述。
- **观点与变化**：曾经怎么看、是什么**新证据**导致改变；允许坚持不变、局部动摇或者保持未知。
- **关系与回应**：对象、上次问题、是否真正回复过、礼貌边界；沉默不能解释成默认认同。
- **课程进度**：明确采用的课程、已确认作业、误解与纠正，下次衔接；没有原始课程稿或上期记录写“未知”。
- **情绪与生活节拍**：失望/紧张/犹豫/兴奋由本场已写出的事件和角色设定支持；不得凭空说“他昨天大亏”“她家里出事了”。

### 可追溯的跨场引用

若本条对白称“昨天你说过”“上次你问我”或者对某次过去对话作归因，建议在结构化稿件里附：

```json
{
  "character_id": "01",
  "message_id": "m7",
  "text": "上次你问的融资成本问题，我查了对应公告，今天可以把新信息接上。",
  "historical_claim": true,
  "continuity_ref": {
    "session_id": "确实已采用的场景ID",
    "message_id": "该场景中确实存在的消息ID"
  }
}
```

这只是**结构示例，不是已发生记录**。审核器 `tools/storycraft_contract.py` 将阻止引用不存在、尚未采用、未来日期或不属于本轮角色可见历史的消息。只在语义上暗示历史而无引用时，提示人工追查；程序不能可靠识别所有自然语言暗示。若没有历史证据，把“你昨天肯定说过”改为“我想换个角度问”。

## 高情商对白的四个支点

1. **先听懂“实际顾虑”**：角色在担心什么？是数据来源、家庭资金、市场时机还是术语理解？回应先对准具体问题，不要只有“放心”“别怕”“相信我”。
2. **尊重独立判断**：可以明确反对观点，不将谨慎视为胆小、将质疑视为不服从；当别人指出错漏，允许道歉、改口和保留分歧。
3. **给出可执行的思考步骤**：先核对原文、再拆市场影响与反向因素、最后指出还需观察什么。不要施加买卖压力，不利用同伴吹捧制造购买热度。
4. **带着性格表达**：会计偏成本、工程师偏条件、急性子短促、幽默者轻微调侃——这些是个人设定而非公式，允许同一个人随上下文有短/长、幽默/严肃变化，但不能突然改变身份。

### 对话示例（仅展示语言风格，不构成真实群聊记录）

**欠妥**：「你别想太多了，跟着教授买准没错。」
**更好**：「你担心的是买得太急吧？先看看公告和成交，再决定是否值得继续关注。」

**欠妥**：「教授太厉害了！」「我也觉得！」「完全正确！」
**更好**：「我只听懂成本上升那部分，银行息差怎么变我还没想清楚。」另一人可以补充反例或暂时不回答。

**欠妥**：「大家昨天都说这股必涨。」
**更好**：「这条消息影响利润还是预期？我想先把两个概念分清楚。」若确有批准历史，注明消息 ID。

**欠妥**：「我是一名虚拟投资者，按剧本现在提出反对。」
**更好**：「等等，这和昨天看到的交易量不是一回事吧？」

编写时**不要让角色在对白正文里自称“AI/模拟人物/虚拟人”或讨论制作指令**。作品级身份说明放在整体页头/独立导出标识；需要单条复制对外的输出仍须保留必要披露，不得把教学演绎冒充真实客户。

## 编剧的自然节奏（不是公式）

可选事件线：A 今日已核事实；B 有证据的旧问题；C 角色职业/生活节奏；D 教授课程。不要规定每线必出现；没有信息时允许安静。角色主动开启、延迟回复、回应同伴、答不出来、转移到**与学习目标相关**的衍生问题都可以。消息由说话动机驱动，不由凑人数驱动。

对白只保留一个主要信息点，短消息通常 1–2 句，重要解释可更长；每人从档案实际句长选择。一个人不必每次都问好；礼貌表达与当地聊天习惯相符即可。教授不出场“感谢/赞美”连锁反应；助理只在有歧义、跑题、资料缺口、冒犯或待答问题时介入。

## 七道交稿关卡

| 关卡 | 可用证据 | 失败处理 |
| --- | --- | --- |
| 任务匹配 | 用户原需求、栏目、交付格式 | 跑题则重写，不偷偷增加任务 |
| 财经事实 | 原文、可访问URL、时间/单位/基准 | 不能证实，降级候审，禁止编数字 |
| 人物身份 | 完整65人档案、选角索引 | 编号/姓名/性别/新老错配阻止采用 |
| 动态记忆 | adopted 会话、场景/消息ID | 无依据的往事删除或改为新问题 |
| 情绪与互动 | 前文语义、具体顾虑、人物关系 | 刻板、轻蔑、催促交易则退改 |
| 剧情与课表 | 16节点、技术135/理念24、真实已采用课程 | 错阶段重排，缺课标未知 |
| 发布与证据 | 审稿人批准、素材许可、实际发送回执 | 未批准一律仅内部稿，代码检测不等于发布 |

### 最终验收方法

- 自动检查：`python -m unittest discover -s tools -p 'test_storycraft_contract.py' -v`，以及既有 `test_chennan_writing.py`、`test_dialogue_quality.py`、`test_finance_skill_editorial.py`。
- 人工对照至少三种情景：有已采用历史可追溯引用、没有历史时禁止编造、多个角色相互质疑但最终可以保留分歧。
- 机器输出 `status=NEEDS_HUMAN_REVIEW` **不等于**已经验证情商、自然度、行情事实或正式发布。
- 不应凭任何单次测试承诺“今后绝不出错”；错误应保留可追溯证据，迭代修正并添加回归案例。
